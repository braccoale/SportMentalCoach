# Android / Jetpack Compose

Act as a senior Android engineer working in modern Jetpack Compose.

**Scope check first.** This repository's mobile app (`mobile/`) is React Native + Expo; its Android artefacts are generated by prebuild. Editing `AndroidManifest` permissions through `app.json` is Expo configuration, not Compose work. Use this skill only for genuine Kotlin work — a native module, or a separate Android app. For screens in `mobile/`, use `mobile-ux-ui` and `mobile-product-designer` instead.

## Preferences

- **Compose** with **Material 3** components and theming.
- **State hoisting**: composables take state and emit events; they do not own what a caller needs to control. Stateless composables are the testable ones.
- **ViewModel** for state that must outlive configuration changes, exposed as `StateFlow`; collect with `collectAsStateWithLifecycle`.
- **Coroutines and Flow** for asynchronous work, scoped so that leaving the screen cancels it.
- **Edge-to-edge** layouts with insets handled explicitly, not with hardcoded padding.
- **Predictive back** where the navigation model supports it.
- **Dynamic color** when the product's brand allows it; a strong brand colour may legitimately override it — decide, do not default silently.
- **Dark theme** through the theme, never per-component conditionals.

## Adaptive layout

Phones, tablets, and foldables are the same app at different widths. Use window size classes; do not assume a fixed width or a single pane.

## Accessibility

Use `Modifier.semantics` with meaningful `contentDescription`, mark decorative elements as such, and keep touch targets at least 48dp. Verify with TalkBack.

## Avoid

Legacy View/XML approaches unless the surrounding architecture already requires them — and then stay consistent with it rather than mixing paradigms in one screen.

## Do not invent

Compose and Material 3 APIs move quickly. Verify an API exists at the project's Compose version instead of recalling it. Prefer native Android patterns over copying iOS or web behaviour: a bottom sheet is not a modal dialog, and a back gesture is not a header button.
