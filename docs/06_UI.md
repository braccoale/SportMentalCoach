# SportMentalCoach — UI (Phase 1)

UI is built with Next.js App Router, Tailwind CSS and shadcn/ui. All
domain-facing copy and taxonomy labels come from the active vertical config
(`lib/core/config`), never hardcoded inline.

---

## Surfaces

| Surface        | Route                  | Group           | Access |
|----------------|------------------------|-----------------|--------|
| Home           | `/`                    | `(dashboard)`   | public |
| Coach listing  | `/coaches`             | `(marketplace)` | public |
| Coach profile  | `/coaches/[slug]`      | `(marketplace)` | public |
| Auth           | `/sign-in`, `/sign-up` | `(login)`       | public |
| Dashboards     | `/dashboard/*`         | `(dashboard)`   | gated  |

The `(marketplace)` route group has its own minimal public header
(`app/(marketplace)/layout.tsx`): brand name + link to the coach listing +
"Accedi". It does not load the authenticated user menu.

## Coach marketplace (Phase 1)

### `/coaches` — discovery (matching, not search)

- Server component, `dynamic = 'force-dynamic'`. Data:
  `getCoachDiscovery(filters, { favoriteIds })` (`lib/core/listings`) — approved
  coaches enriched with rating aggregate (`getRatingSummaries`), languages,
  years, athlete levels, and a **deterministic quality score** that drives the
  default **"Consigliati"** sort. Per-card **match reasons** explain *why*
  (matched filters first, then quality signals); the top matches get a
  **"Consigliato"** badge. No AI.
- **Filters** (`<form method="get">`, keeps routing & old `?sport=&specialty=`
  links): sport, specialty (obiettivo), livello, lingua, **solo certificati**,
  **ordina** (Consigliati / Valutazione / Prezzo / Esperienza), and a
  **Preferiti** toggle for logged-in users. "Azzera" clears.
- **Rich cards** (`components/coach-card.tsx`): photo, name, verified +
  certified badges, ★ rating (count), headline, match-reason chips, key facts
  (sport · lingue · anni), price, "Vedi profilo →", and a **favourite heart**
  (`components/favorite-button.tsx` → `toggleFavoriteAction` → `favorites`
  table; optimistic).
- **AI matching** is a **placeholder** banner ("Trova il mio match · Presto");
  **Salva ricerca** is likewise a placeholder.
- **No-result** (with filters) shows an "azzera" CTA **plus** a "Forse ti
  interessano" rail of the top unfiltered coaches (second chance). Empty (no
  filters) shows a neutral state.

### `/coaches/[slug]` — profile (redesigned, trust-first)

Mobile-first, two-column on desktop (sticky booking aside on the right; on
mobile the booking card sits right under the hero via flex `order`). Sequence:
**hero** (avatar, name, verified + certified badges, rating or "Nuovo", key
facts) → **intro video** (YouTube/Vimeo embed, link fallback) → **approccio**
(philosophy/bio) → **credenziali e verifica** → **esperienza** (sports +
athlete levels + languages) → **specializzazioni** → **servizi** →
**disponibilità** → **recensioni** (verified, aggregate ★) → **sicurezza e
tutela** + **FAQ** + **politica di cancellazione** (`components/trust-sections`).
Reviews are written by athletes on **completed** bookings from the athlete
dashboard (`ReviewForm` → `createReviewAction` → `lib/core/reviews`). Reusable
bits: `RatingStars`, `CoachAvatar`, `CertifiedBadge`, `BookingRequest`.

### `/coaches/[slug]` — (legacy reference)

- Server component; `getCoachBySlug(slug)` returns the approved provider with
  its `profiles` row and active `services`, or `null` → `notFound()`.
- Shows headline, description/bio, hourly rate, sport and specialty chips, and
  a list of service cards (title, duration, price).
- **Placeholder CTA**: a disabled `Button` with `copy['booking.cta']`
  ("Richiedi sessione") and a note that booking is coming soon. Booking is not
  implemented in this step.

## Public homepage & navigation

- **Homepage** (`/`, `app/(dashboard)/page.tsx`): a Kai Pai marketing page —
  hero with the brand + tagline (from the vertical config) and two CTAs
  (**Trova un coach** → `/coaches`, **Inizia ora** → `/sign-up`), a "Come
  funziona" 3-step section, an audiences section (atleti / coach / club), and a
  closing CTA band. No Stripe/pricing references, so it renders unchanged with
  billing disabled.
- **Public header** (`(dashboard)` + `(marketplace)` layouts): brand → `/`,
  a **Trova un coach** link → `/coaches`, and sign-in / sign-up (or the user
  menu). Pricing only appears when `BILLING_ENABLED`.
- **Footer**: present site-wide (see below).
- **Demo accounts** (`components/demo-accounts.tsx`): a dev-only box
  (`process.env.NODE_ENV !== 'production'`) listing seeded credentials (admin +
  demo coaches). Shown on the homepage and the sign-in page; never ships to
  production.

## Notifications

- `NotificationBell` (`components/notification-bell.tsx`) sits in the dashboard
  header. It polls `/api/notifications` (SWR, 30s), shows an unread badge, and a
  dropdown of the last 10 (unread dot, click → mark read + navigate to
  `data.link`, "Segna tutte come lette"). Hidden for logged-out users.
- `/dashboard/notifications` is the full list with per-item and "mark all as
  read". Both surfaces are powered by the generic `lib/core/notifications`.
- `/dashboard/notifications/preferences` is the **email preferences** page: a
  per-type email toggle (default on) backed by `notification_preferences`. A
  note makes clear in-app notifications stay always on. Linked from the
  notifications page header ("Preferenze").

## Dashboard navigation

- The dashboard sidebar (`app/(dashboard)/dashboard/layout.tsx`) is role-aware:
  it fetches the current user's roles from `/api/user/roles` and renders a link
  to each role dashboard the user holds (athlete / coach / club / admin, labels
  from the vertical config), above the account settings links. Route mapping
  lives in `lib/core/auth/role-routes.ts` (a pure, non-`server-only` module so
  it is safe to import from the client).

## Branding

- The product is **Kai Pai**. The brand name comes from the vertical config
  (`copy['brand.name']`); headers and the footer read it from there. The page
  `<title>` is set in `app/layout.tsx`.

## Avatars / profile photos

- `CoachAvatar` (`components/coach-visuals.tsx`) renders `profiles.avatar_url`
  via the shadcn `Avatar`, falling back to initials (`initials()` in
  `lib/core/format.ts`). Used on coach cards, the coach profile header, and the
  dashboards.
- Athletes and coaches set their photo from their dashboard via `PhotoForm`
  (`app/(dashboard)/dashboard/photo-form.tsx`) → `updatePhotoAction` →
  `setAvatarUrl()`. Phase 1 stores an image **URL** (no file upload backend
  yet); the field validates as a URL and an empty value clears the photo.

## Certification badge

- `CertifiedBadge` shows a `BadgeCheck` icon, coloured orange when the coach is
  Kai Pai Academy certified (`provider_profiles.is_kaipai_certified`) and greyed
  out otherwise, with a `title`/`aria-label` from `copy['coach.certified.yes'|
  'no']`. Shown on each listing card and (with label) on the profile header.

## Footer

- `Footer` (`components/footer.tsx`) is a standard site footer with brand +
  tagline, contacts (email / phone / location) and social links
  (Instagram / Facebook / LinkedIn / YouTube). Rendered by the `(marketplace)`
  and `(dashboard)` layouts.

## Dashboards (Phase 1)

All dashboards are role-guarded server components under `/dashboard/*` and share
the settings chrome. Each shows the **PhotoForm** (set avatar URL).

### Home — `/dashboard`

- Neutral account home (no SaaS-starter "Team Settings" wording). Shows
  **"I tuoi spazi"** (quick links to the dashboards of every role the user
  holds, from `/api/user/roles`), the **Organizzazione** members list and
  **Invita un membro** form (the repurposed `teams`/`team_members`, relabeled).
- The subscription card (**Abbonamento**) renders only when `BILLING_ENABLED`,
  so with billing off the page shows no billing wording. The sidebar item is
  **Dashboard** (was "Team").

### Athlete — `/dashboard/athlete`

- Grouped booking sections: **In attesa** (requested), **Accettate** (accepted),
  **Storico** (declined / cancelled / completed). Empty sections are hidden.
- A full empty state (no requests) shows a dashed-border card with a
  "Trova un coach" CTA to `/coaches`.

### Coach — `/dashboard/coach`

- **Status banner** (`provider_profiles.status`): coloured by state with
  guidance text (informational only).
- **Onboarding progress** (`OnboardingProgress`, shown while not `approved`): a
  "Completa il tuo profilo" card with a progress bar and a 4-step checklist
  (profilo base → sport/specializzazioni → servizi → invia per la revisione),
  a "Prossimo passo" hint with in-page "Vai →" anchors to the relevant editor,
  and the **"Invia per la revisione"** button — enabled only when steps 1–3 are
  complete (`getCoachOnboarding`). Submitting moves `draft|rejected → pending`;
  it never auto-approves.
- **ProfileEditor** (client, `useActionState`): edits headline, bio
  (`provider_profiles.description`), sports (`categories`) and specialties as
  checkbox groups sourced from the vertical taxonomy. Saving never changes the
  status — an `approved` profile stays approved (edits go live), a non-approved
  one stays non-public until the admin approves.
- **ServicesEditor**: per-service edit/delete forms + an add form. Price is
  entered in euros and stored as cents. All ops are coach-ownership-checked in
  `lib/core/services`.
- Booking requests (pending + history) with Accetta / Rifiuta, as before.

## Shared helpers

- `lib/core/format.ts` — `formatPrice`, `formatDateTime`, `initials`.
- `lib/core/bookings` — `bookingStatusLabel` / `bookingStatusTone` (label +
  badge classes) shared by the athlete and coach dashboards.
- `lib/fetcher.ts` — the single SWR `fetcher` used by all client components.
- `lib/core/result.ts` — shared `Result<T>` type for domain operations
  (bookings, services, admin).

## Coach area (`/dashboard/coach`)

Refactored from a single monolithic page into a tabbed section
(`app/(dashboard)/dashboard/coach/layout.tsx` → `coach-nav.tsx`, branded with
the Kai Pai mark). Opening the area lands on the **Dashboard** tab.

| Tab       | Route                       | Contents                                                                                                     |
| --------- | --------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Dashboard | `/dashboard/coach`          | Summary cards (pending / accepted / total / reviews) + pending requests, accepted sessions, history, reviews |
| Coach     | `/dashboard/coach/profile`  | Status banner (non-approved only), onboarding, photo card (green upload button + "Approvato" badge), Account Information, video upload, profile editor |
| Servizi   | `/dashboard/coach/services` | Services editor (create/edit/delete) + weekly availability (create/**edit**/delete)                          |

Notable pieces:

- **Presentation video** (`video-upload.tsx` → `/api/upload-video`): uploads to
  Supabase Storage when configured, else local `public/uploads/`
  (`lib/core/storage.ts`). Stored on the existing `provider_profiles.video_url`;
  the public profile plays uploaded files inline and keeps YouTube/Vimeo embeds.
- **Experience**: `provider_profiles.coach_since` (date). Years are derived via
  `yearsSince()` and mirrored into the legacy `years_experience` integer on save
  so listings / cards / sorting are unchanged.
- **Account Information** moved out of the removed `/dashboard/general` page into
  `components/account-info-card.tsx`, rendered on the Coach tab.
- **Auth-aware header**: `components/user-avatar.tsx` (uppercase initials on a
  brand-red disc) is shown on the landing (`site-nav.tsx`) and marketplace
  (`marketplace-auth-nav.tsx`) headers when `/api/user` resolves — shared
  app-wide via the root layout's SWR fallback.

## Conventions

- Prices are stored as integer cents; rendered with `formatPrice()`
  (`lib/core/format.ts`, `Intl.NumberFormat`, default `it-IT` / `EUR`).
- Taxonomy keys are persisted; labels are always resolved at render time via
  `findTaxonomyItem()` so a vertical swap changes all labels.
- No payment UI in Phase 1.
